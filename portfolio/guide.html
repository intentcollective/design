Make this site
your own.

This portfolio is a template. Everything you see, from the name in the corner to the color of the links, comes from a few small files you can change without writing code. This guide moves in four levels, from changing your name to building your own layouts. Stop at whichever level you need.

Before you start

How the site is built

The site is plain HTML, CSS and JavaScript. There is no framework and no build step. The HTML pages are empty frames. When someone opens a page, a small script reads your content files and fills the frame.

portfolio/
  index.html        Works page, the first page people see
  project.html      One page that shows any project
  resume.html       Source for your resume PDF. Not in the menu.
  about.html        About
  print.html        The page your PDF portfolio is made from
  content/
    settings.json   Name, menu, colors, typeface, project order
    projects/       One file per project
    resume.json
    about.json
  images/           Your images, one folder per project
  files/            Your PDFs
  css/style.css     The look of the whole site
  js/               The engine. You rarely need to open it.

Three ways to edit

Every change in this guide can be made in any of these three ways. Pick the one you are comfortable with.

  1. Ask an AI. Give an AI assistant access to your repository, or paste in the file, and describe what you want. “Add a two-column gallery after the Process text in tamara.json, using these two images.” Always check the result in your browser.
  2. Use the Pages CMS forms. Go to app.pagescms.org, sign in with GitHub and open your repository. The template includes a .pages.yml file that tells Pages CMS which fields to show. Every save becomes a commit.
  3. Edit on GitHub. Open a file on github.com, click the pencil icon, change it and commit. Upload images with “Add file” then “Upload files.”

Preview on your computer

Double-clicking index.html shows an error, because browsers don’t let a page read other files straight from your disk. Run a tiny local server instead. On a Mac, open Terminal in the portfolio folder and type the line below, then visit http://localhost:8000.

python3 -m http.server 8000

In VS Code, the Live Server extension does the same with one click.

Level 1
Settings

Open content/settings.json. This one file controls everything that appears on every page.

"name": "Sena Hart",
"role": "Graphic Designer",
"email": "hello@example.com",
"linkedin": "https://www.linkedin.com/in/your-name/",

The header

Each item in headline becomes one large line. The line {rotate} is replaced by the changing words, shown in your accent color. For a still header, leave only one word in the list, or remove the {rotate} line.

"headline": ["I build", "{rotate}", "out of words."],
"rotatingWords": ["cities", "books", "films", "posters"],

Write a line that only you could say. “Graphic designer based in Savannah” is true of hundreds of people. A point of view is what makes a reviewer remember you.

The menu

Each item in menu has a label and a link. Rename, reorder, add or remove items freely. Set "newTab": true for links that leave your site or open a PDF.

The Resume item links straight to your PDF, because that is the version reviewers save and forward. If you would rather show a web resume, change its link to resume.html. That page is already built from content/resume.json.

"menu": [
  { "label": "Works", "link": "index.html" },
  { "label": "Resume", "link": "files/your-name-resume.pdf", "newTab": true },
  { "label": "Li", "link": "https://www.linkedin.com/in/your-name/", "newTab": true },
  { "label": "About", "link": "about.html" }
],

Colors and typeface

Change the colors in theme. Any CSS color works. To use a Google Font, type its exact name and set googleFont to true.

"theme": {
  "background": "#000000",
  "text": "#f2f2f0",
  "accent": "#ff3b2f",
  "font": "Space Grotesk",
  "googleFont": true
}

Check contrast. Text must stay readable against the background, for every visitor. Paste both colors into a contrast checker and aim for a ratio of at least 4.5 to 1.

If something breaks

JSON is strict about punctuation. If a page shows a red box saying there is a typo, look near the line it names for a missing comma between items, a missing quote mark, or an extra comma after the last item in a list.

Level 2
Projects

Add a project

  1. Copy any file in content/projects and rename it, for example bus-stop-zine.json. Use lowercase letters and hyphens.
  2. Make a folder with the same name in images/projects and put your images there.
  3. Add the name, without .json, to the works list in settings.json. The order of that list is the order on your Works page.

The top of a project

These fields fill the header of the project page and the card on the Works page.

"title": "Tamara",
"discipline": "Poster, Lettering",
"year": "2025",
"summary": "One sentence. What it is and why it matters.",
"role": "Concept, lettering, layout",
"tools": "Illustrator, InDesign",
"timeline": "4 weeks",
"context": "Typography III",
"cover": "images/projects/tamara/cover.jpg",
"coverAlt": "Describe the image for someone who can’t see it",

Blocks

Below the header, a project page is a list of blocks, stacked in the order you write them. Mix them however the project needs. A typical order is brief, idea, research, process, iterations, final work, reflection.

text

A heading on the left and paragraphs on the right. A blank line starts a new paragraph.

{ "type": "text",
  "heading": "Process",
  "body": "First paragraph.\n\nSecond paragraph." }

image

Width is full (edge to edge), wide or narrow. A background color adds a frame around the image.

{ "type": "image",
  "src": "images/projects/tamara/detail.jpg",
  "alt": "Close-up of the lettering",
  "width": "wide",
  "background": "#efefed",
  "caption": "Optional caption" }

gallery

Two to four images side by side. ratio crops them all to the same shape.

{ "type": "gallery",
  "columns": 3,
  "ratio": "4/5",
  "images": [
    { "src": "images/.../sketch1.jpg", "alt": "..." },
    { "src": "images/.../sketch2.jpg", "alt": "..." },
    { "src": "images/.../sketch3.jpg", "alt": "..." }
  ],
  "caption": "Three rounds of sketches" }

video

Paste a Vimeo or YouTube link, or the path to an .mp4 in your images folder. For a short silent loop, set autoplay to true.

{ "type": "video",
  "url": "https://vimeo.com/88666098",
  "caption": "Final film" }

quote

One large line. Use it once per project, at most.

{ "type": "quote",
  "text": "The constraint was the idea." }

compare

A before and after slider. Good for showing a redesign or a big revision.

{ "type": "compare",
  "before": "images/.../draft.jpg",
  "after": "images/.../final.jpg",
  "caption": "Midterm draft and final" }

placeholder

A dashed box that marks what still needs to go in. The example projects use these to show where process images belong. Replace every one before you share your site.

{ "type": "placeholder",
  "label": "Research wall photos",
  "ratio": "16/9" }

spacer

Extra breathing room. small, medium or large.

{ "type": "spacer", "size": "large" }

Preparing images

Export images 2000 pixels wide for full and wide, and 1400 pixels for narrow and gallery images. Save photos as JPG at about 80 percent quality. Keep each file under 500 KB if you can, because a slow site loses reviewers before your work appears.

Level 3
Style

Open css/style.css. The top of the file holds the tokens, named values used everywhere else. Change one and the whole site follows.

:root {
  --text-hero: clamp(3.25rem, 10.5vw, 11.5rem);
  --margin: clamp(1.25rem, 4vw, 3rem);
  --gap: clamp(1.25rem, 3vw, 2.5rem);
  --grid-columns: 2;
}

What clamp() does

clamp(3.25rem, 10.5vw, 11.5rem) means “10.5 percent of the window width, but never smaller than 3.25rem or larger than 11.5rem.” That one line is why the header fills a laptop screen and still fits on a phone. rem is the browser’s base text size, usually 16 pixels.

Things to try

  • Set --grid-columns to 3 for a denser Works page.
  • Change the card shape by editing aspect-ratio: 4 / 5 in .card__media. Try 1 / 1 or 3 / 2.
  • Make the header heavier by changing font-weight in .hero__headline.
  • Open your browser’s developer tools (right-click, Inspect), select any element and edit its styles live. Nothing is saved, so experiment freely, then copy what you like into style.css.

Level 4
Structure

How a page gets built

  1. The browser loads an HTML file, for example project.html?p=tamara.
  2. js/site.js reads settings.json, sets your colors and builds the menu and footer.
  3. js/pages.js looks at data-page on the body tag and runs the matching function. For a project, it reads content/projects/tamara.json.
  4. Each block is turned into HTML by the function with the same name in the Blocks section of site.js.

Make a new block type

Say you want a block that shows a color palette. Add a function to Blocks in site.js, a style to style.css, then use it in any project file.

// site.js, inside Blocks
palette(b) {
  return `<div class="b-palette">${
    b.colors.map(c => `<span style="background:${c}"></span>`).join("")
  }</div>`;
},

/* style.css */
.b-palette { display: flex; height: 8rem; }
.b-palette span { flex: 1; }

// tamara.json
{ "type": "palette", "colors": ["#c8202f", "#ffffff", "#111111"] }

A completely custom page

For a project that needs a layout the blocks can’t make, write it by hand. Copy about.html, delete the script tag for pages.js, keep site.js so the menu still appears, and write your own HTML inside <main>. Then link to that file from a card or a text block.

Publish

GitHub Pages

  1. In your repository on github.com, open Settings, then Pages.
  2. Under “Build and deployment,” choose “Deploy from a branch,” pick main and the root folder, and save.
  3. After a minute your site is live at your-username.github.io/repository-name/portfolio/. Every later commit updates it automatically.

You can connect your own domain in the same settings screen.

Your PDFs

Many companies still ask for a PDF. Open print.html in your browser, choose File, then Print, then Save as PDF. Set the layout to landscape, margins to none, and turn on background graphics. Save it into files with the name used in settings.json. Do the same with resume.html, in portrait, for your resume. Regenerate both every time you change a project.

What reviewers look for

Most reviewers spend less than a minute on a portfolio before deciding whether to look closer. Design for that minute.

  • Lead with your best work. The first two projects decide whether anyone sees the rest. Six strong projects beat ten uneven ones.
  • Make the summary do the work. One sentence per project that says what it is and why it’s interesting. Many reviewers read only that.
  • Show how you think. Sketches, rejected directions and the reason you changed course tell a studio more than the final image. That is why every project here has a process section.
  • Say what you did. Name your role, especially on group work.
  • Keep it fast. Compress your images and test on your phone.
  • Make contact easy. Email, resume and LinkedIn should never be more than one click away.
  • Leave nothing unfinished. Replace every placeholder and check every link before you send the address to anyone.
